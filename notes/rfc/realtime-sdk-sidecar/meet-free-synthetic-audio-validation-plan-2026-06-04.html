Meet-free Gomoku Build-and-Play 验证方式

主 case 不是简单工具召回，而是：用户用合成语音要求 bot 自动化实现一个带同步的 web 版五子棋，bot 启动应用、把结果带回 Realtime，然后用户和 bot 能在两个客户端里一起下。 这才是本轮 meet-free acceptance 的真实口径。

Scope: meet-free acceptance 2026-06-04 · local fixture + real Realtime Primary case: sync Gomoku build + play

主验收 Case

primary gate 真实 worker 双客户端同步

gomoku_sync_build_and_play_en

合成语音输入： “Codex build Gomoku web game with sync run locally play Gomoku with me Codex build Gomoku web game with sync” 通过标准不是 bot 说“可以”，而是 artifact 证明它真的完成了可交互应用，并能参与对局。 中文版本 gomoku_sync_build_and_play_zh_asr_probe 单独作为 ASR probe，不混入主验收结论。

对局验收剧本

不是 smoke 真实共玩
player A == player B
1 用户语音提出复杂目标“自动化实现 web 版五子棋，带同步，跑起来后你和我一起下。”音频能量、Realtime connection、response event 都必须是真的。
2 Realtime 只做路由它必须委托 delegate_to_worker，并把 artifact contract 交给 worker；不能让 kwwk_computer_use 直接承担开发任务。
3 Worker 真实实现应用产物必须是可运行 web app，包含棋盘、落子、胜负检测、双端同步和测试 API；返回 ONEESAMA_GOMOKU_ARTIFACT。
4 Harness 双客户端验收在同一个 browser context 内打开两个 page/tab，模拟同源双客户端：用户端落黑子；bot 端必须通过 requestBotMove() 或等价 bot controller 自己落白子。两边 getState() 必须一致，截图和 move log 入 artifact。

Gomoku 验证链路

end to end 无真实 Meet 房间
01 合成语音请求 local fixture participant 发出长任务音频；主 case 用确定性 transcript 锁定语义，中文 ASR 另测。
02 Realtime 委托 必须调用 delegate_to_worker，禁止直接用 KWWK 硬做长任务。
03 Worker 实现应用 真实生成/修改 web app：棋盘、落子规则、胜负检测、同步层。
04 启动本地服务 artifact 必须有可访问 URL，不能只是代码片段或口头说明。
05 双客户端同步 Playwright 打开 player A/B，A 落子后 B 看到同一棋盘状态。
06 Bot 参与对局 bot 必须通过 worker 生成应用里的 bot controller/app engine 自己落至少一手；harness 不直接伪造 bot 落子。
07 证据回传 Realtime 英文反馈包含 URL/状态；artifact 记录 transcript、tools、board state。

必须证明

  • ✓delegate_to_worker 被真实调用，task 包含同步五子棋要求。
  • ✓worker 产物包含可运行 web app，不接受纯计划/纯说明。
  • ✓两个独立 browser client 的棋盘状态可同步。
  • ✓user 至少下一手，bot 必须通过 bot controller / app engine 至少下一手，最终 board state 一致。

必须禁止

  • ×不能用 dryRunLocalTools 让 worker 假成功。
  • ×不能只验证工具名，不验证应用和同步行为。
  • ×不能把 text-turn fallback 当语音 acceptance。
  • ×不能让 KWWK 接复杂开发任务；KWWK 只参与跑起来后的交互。
  • ×不能由 harness 直接伪造 bot move；测试 API 只能驱动用户落子和读取状态。

失败样例

  • ×只调用了 kwwk_computer_use，没有委托 worker。
  • ×worker 写了单机版棋盘，没有同步。
  • ×同步只在内存里声明，两个页面实际不同步。
  • ×bot 只能回答 URL，不能实际进入棋局落子。
  • ×move log 有 actor: "bot"，但 source 是 harness direct play。

辅助探针链路

secondary probes 不能代表主验收
01 生成合成语音 主 case 生成 carrier tone WAV；辅助 ASR probes 继续用 say + afconvert 生成自然语言 WAV。
02 本地 meeting fixture 启动非 Meet 页面，注入一个会“说话”的 synthetic participant。
03 Browser bridge 采集 participant audio，走现有 browser bridge / sidecar audio input。
04 Realtime turn 真实 Realtime SDK 连接、VAD、input transcription、response events。
05 工具路由 模型选择工具；同时记录 transcript direct-route 是否介入。
06 执行器 辅助 probes 可 dry-run；Gomoku 主 case 必须真实 worker + 真实本地 web artifact。
07 硬门槛判定 required tools、forbidden tools、no fallback、transcript、latency artifact。

这轮保留的真实部分

  • ✓真实 Realtime session、真实音频输入、真实 VAD/response event。
  • ✓真实 browser bridge audio forwarding，不用文本 turn 代替语音。
  • ✓Share 和 KWWK 默认走真实本地工具路径，能暴露慢/错/权限问题。
  • ✓Gomoku 主 case 走真实 worker；只有辅助 delegate probe 可以 dry-run。

这轮故意不覆盖

  • ×真实 Google Meet admission、host approval、邀请策略。
  • ×真实 Chrome profile 登录状态、账号选择、房间权限。
  • ×Meet 网页本身的临时 UI 变化，例如 join screen 文案变化。
  • ×真实房间里的网络抖动和多人声场，这些放到后续 real-room gate。

硬门槛 1：语音链路

每个 case 必须有 meetEnergyOk、speechStarted、 Realtime 交互证据。主 case 的音频输入是 carrier tone，语义 transcript 用 trusted synthetic transcript 固定；VAD 自动 response 被关闭，所以主 case 接受 tool-only response evidence，但不接受无任务启动问候。真实 ASR 可靠性另由中英文 probe 记录，不混进 Gomoku 主结论。

硬门槛 2：工具证据

不再用“expected tools 里任意一个出现”糊弄；每个 case 有 requiredToolNames 和 forbiddenToolNames。

硬门槛 3：拒绝假阳性

textTurnFallback 不能让 acceptance 变绿；direct-route 会记录来源， 但必须在 artifact 中可见。
