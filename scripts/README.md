# scripts/

Operational shell scripts for the oneesama codebase. Each script is a thin
bash wrapper that composes the binaries in `../cmd/` and the live HTTP
endpoints they expose. If a new script lands here, add a row to the table
below in the same commit. Task #277.

## Live service control + health

| Script                             | Purpose                                                                                                                                                                                                                                      | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `oneesama-live.sh`                 | Canonical env/preflight/exec wrapper for a single live `oneesama` subcommand.                                                                                                                                                                | Sources the live env files with `set -a` from persistent `${XDG_CONFIG_HOME:-$HOME/.config}/oneesama/live-env/` defaults, rejects stale alias conflicts, and for `slack-agent` requires the Pi foreground posture (`pi_first_live`, `oneesama-pi`, `live`, `shadow=false`, workspace policy) unless `--allow-legacy-slack` is explicitly passed for local/dev smoke tests. For `meeting-agent`, Realtime placement defaults to sidecar; inline Meet SDK on Google Meet has been removed and preflight rejects `*_OPENAI_REALTIME_RUNTIME_PLACEMENT=inline`. |
| `oneesama-live-screen.sh`          | Canonical detached `screen` lifecycle wrapper for live services.                                                                                                                                                                             | Defaults to `meeting-agent`; refuses to start or restart `slack-agent` unless `--allow-slack-agent-restart` is passed, and always routes startup/postcheck through `oneesama-live.sh`.                                                                                                                                                                                                                                                                                                                                                                      |
| `oneesama-monitor.sh`              | Probe live `/healthz` + `/slack/status` + `/slack/triage/audit` for both services; exit non-zero on any red flag.                                                                                                                            | Default audit window `3h` (env: `ONEESAMA_MONITOR_AUDIT_WINDOW`). When `ONEESAMA_STATUS_OUTPUT_DIR` is set, writes `monitor-result.json` for the report wrapper (task #295).                                                                                                                                                                                                                                                                                                                                                                                |
| `oneesama-triage-quality-sweep.sh` | Walk the triage status feed for a window and bucket runs into red (failures / invalid persona JSON / placeholder summaries) and review (high-context / link-context / low-confidence no-action) buckets.                                     | Default window inherits from monitor; thresholds come from the live audit (`qualityThresholds` block, task #285) with `7000` / `0.75` fallback. Writes `triage-quality-result.json` when `ONEESAMA_STATUS_OUTPUT_DIR` is set.                                                                                                                                                                                                                                                                                                                               |
| `oneesama-status-report.sh`        | Run `oneesama-monitor.sh` + `oneesama-triage-quality-sweep.sh` into a shared output dir, optionally add live triage benchmark fixtures, then emit a merged `status-report.json` (schema `oneesama.status-report.v1`) and `status-report.md`. | Exit 0 only when enabled checks are ok. Output dir defaults to `mktemp -d`; override via `ONEESAMA_STATUS_REPORT_OUTPUT_DIR`. Enable live fixtures with `ONEESAMA_STATUS_REPORT_TRIAGE_BENCHMARK=1`.                                                                                                                                                                                                                                                                                                                                                        |

`benchmark:realtime-real-app-control:suite` writes per-case
`final.appControl.timing` and top-level `liveModelFirstLatency` evidence for the
live model-first CU path. `acceptance:realtime-live-sidecar:preflight` validates
URL/profile wiring only. Its JSON includes
`admissionPreconditions.roomAdmissionVerified:false` because the strict gate
still needs a real Meet room or host/invited profile that admits the synthetic
speaker.

`npm run acceptance:realtime-live-sidecar:auto-room` removes the manual Meet URL
dependency by creating a temporary Google Calendar event with Meet conference
data, using `GOOGLE_CLIENT_ID` / `GOOGLE_REFRESH_TOKEN` from the environment or
`MAB_WORKSPACE_TOOLS_ENV_FILE`, then deleting that event after the gate finishes.
Run `npm run acceptance:realtime-live-sidecar:auto-room:preflight` first to
verify Calendar credentials and profile/admission wiring without creating an
event. Auto-room proves room creation and cleanup, but it does not bypass Google
Meet admission policy: strict acceptance still needs an authenticated main
bot/speaker profile or host admission actor when the generated room says guests
must be invited or admitted. Preflight fails fast with
`calendar_auto_room_admission_path_missing` when Calendar credentials are present
but no authenticated/admission path is configured.

The meet-free synthetic-Realtime gate is
`npm run benchmark:realtime-synthetic-share`: it launches the local Meet fixture,
generates a real synthetic-speaker WAV, feeds that audio into the real Realtime
sidecar, and requires a real share/app tool call without using a Google Meet
room or admission flow. This is the first integration loop to keep green before
debugging real-room admission. Its default synthetic share request is English so
macOS TTS and Realtime ASR preserve the app-control intent; multilingual recall
coverage remains in the text/tool-recall gates. The default utterance is a
short repeated command (`Share Chrome window...`) rather than a natural long
sentence, because this gate is intended to prove the audio->Realtime->tool
integration boundary, not stress macOS TTS phrasing. The local fixture loops
that short synthetic-speaker audio by default so Realtime session warm-up jitter
cannot swallow the only spoken turn.

Strict real-room gates can enable a harness-only host admission actor with
`MAB_REAL_MEET_HOST_ADMISSION=1` and
`MAB_HOST_ADMISSION_BROWSER_USER_DATA_DIR=/path/to/separate-host-profile`.
The host profile must be separate from both `MAB_BROWSER_USER_DATA_DIR` and
`MAB_SYNTHETIC_SPEAKER_BROWSER_USER_DATA_DIR`. When
`MAB_SYNTHETIC_SPEAKER_INVITE_EMAIL` is set, the actor first attempts the Meet
invite flow, then keeps polling host-side Admit/Let in/Allow controls while the
synthetic speaker joins. Acceptance artifacts include `hostAdmission` evidence
so room-admission failures can distinguish disabled host automation, invalid
profile configuration, missing invite UI, and host-side Admit clicks.

Realtime benchmark scripts that create Realtime sidecar sessions share a local
cross-process lock by default. This prevents `benchmark:realtime-tool-recall`,
`benchmark:realtime-tool-lanes`, and `benchmark:realtime-sidecar-audio` from
creating false failures by running concurrently against the same meeting-agent
and Realtime resources. Set `MAB_REALTIME_BENCHMARK_LOCK=0` only for
intentional stress testing.

## Conventions

- All shell scripts use `set -euo pipefail` (or `set -eu` for POSIX `sh`).
- Required external tools are checked with a `need <tool>` helper near the
  top of the script (curl, jq, docker, etc.). If a script gains a new tool
  dep, add it to the corresponding `need` call.
- Scripts read configuration from `ONEESAMA_*` env vars (sometimes with
  `MAB_*` aliases for backwards compatibility). See `pkg/config/raw_env.go`
  for the canonical env-variable list consumed by the binaries.
- For shared structured output across scripts, set `ONEESAMA_STATUS_OUTPUT_DIR`
  and use `oneesama-status-report.sh` as the merge surface (task #295).
