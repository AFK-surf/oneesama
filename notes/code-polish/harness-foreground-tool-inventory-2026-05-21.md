# Harness Foreground Tool Inventory

Date: 2026-05-21
Anchor task: #327
RFC: `notes/rfc/oneesama-harness-cache-tool-stability-rfc-2026-05-21.md`

## Purpose

This inventory pins the foreground tool surface that affects Oneesama cache
locality. A new foreground tool is a migration, not a casual helper. Prefer one
of these before adding a schema:

1. Add a parameter to an existing stable foreground tool.
2. Route the capability through bounded worker delegation.
3. Route bot-owned Browser / Computer Use through `control_shared_browser_surface`.
4. Route existing shared macOS app operation through `kwwk_computer_use`.
5. Add a documented approval gate if the operation mutates external state.

2026-06-01 update: `control_shared_app_window` gained `executionMode` so simple
shared-app actions can stay on the KWWK / direct backend while complex
app-control goals explicitly delegate to the Computer Use worker path.

2026-06-02 update: low-level app-control `operations` were removed from the
foreground Realtime schema. `control_shared_app_window` now exposes natural
language `instruction` plus `executionMode`; KWWK/direct or Codex/delegate owns
the observe/plan/act/verify loop. The direct helper accepts instruction-only
bounded observe/key/type/scroll requests. Browser local-tool handling strips
stale top-level and `context.operations` arguments before dry-run simulation or
host POST; the Go `/tools/control_shared_app_window` handler strips the same
stale primitives, and the KWWK helper no longer reads operations from context.
Old prompts cannot bypass the foreground schema cleanup.

2026-06-02 update: `control_shared_app_window` description now explicitly
classifies browser tab switching (`切换 tab` / `切到下一个标签页`) as direct
shared-app control. This changed only the foreground tool description hash; it
does not add a new tool or reintroduce primitive operation arrays.

2026-06-02 update: raw TS and Go `buildRealtimeSessionConfig()` now default to
the live-safe tool surface. Browser/demo-surface tools remain in the full schema
only for explicit opt-in or the server-side demo-surface gate.

2026-06-02 update: `kwwk_computer_use` is now the default Realtime 2 foreground
tool for simple bounded shared-app operations. It accepts a natural-language
`instruction` and optional app/window target fields; Realtime must not generate
action-specific tool names, operation arrays, or coordinates. The legacy
`control_shared_app_window` route remains as an HTTP compatibility alias, but it
is filtered out of the default live-safe Realtime tool surface so the model sees
one Computer Use entrypoint.

2026-06-01 update: hidden deprecated aliases (`delegate_to_codex`,
`delegate_status`, `list_shareable_apps`, `present_app_share`) and older
fine-grained helper names are no longer foreground inventory metadata. The Go
foreground inventory now only documents tools that are actually present in
`defaultRealtimeToolDefinitions()`.

## Realtime Tool Classes

Source of truth in code: `internal/meetingagent/realtime_tool_inventory.go`.

| Class                 | Meaning                                                                                                       | Examples                                                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `stable_foreground`   | Always part of the realtime foreground schema. Changes here can invalidate prompt/tool cache and need review. | `delegate_to_worker`, `send_meet_chat`, `share_existing_app_window`, `kwwk_computer_use`, `current_user_identity`, `now`  |
| `optional_foreground` | Foreground schema exposed only behind a runtime/product gate.                                                 | `open_shared_browser_surface`, `create_shared_workspace`, `control_shared_browser_surface`, `stop_shared_browser_surface` |

Non-foreground helper names are intentionally not represented as
`RealtimeForegroundToolInventory` classes. GitHub/Linear/Slack/Notion
fine-grained lookup, memory read/write, URL fetch, visual avatar/HUD tools,
Slack file/canvas helpers, shell/file tools, and deep codebase work must stay
behind worker/session capabilities or explicit router-only test fixtures.

| Runtime avatar/HUD          | Video, speaking, thinking, and tool-call status should be driven by audio/tool/job telemetry, not foreground visual-only model tools                          |

## Migration Checklist

When changing a foreground tool schema:

1. Update `realtime_tool_inventory.go` with the tool class, gate, and notes.
2. Update `harness-foreground-tool-inventory-2026-05-21.md` or add a dated
   companion note if the change is a migration.
3. Update the golden hashes in `realtime_tool_hash_test.go`.
4. Explain whether the capability could have been a worker skill or
   `control_shared_browser_surface` parameter instead.
5. Run `go test ./internal/meetingagent -run 'TestRealtimeTool' -count=1` and
   the normal full validation suite.

If any of those steps feels excessive, the proposed change is probably too
small for a new foreground tool.
