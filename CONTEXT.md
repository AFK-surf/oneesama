# Oneesama

Oneesama is a realtime avatar and assistant system that can appear across local
and operator-facing surfaces while preserving clear ownership of voice, visual
context, control, and diagnostics.

## Language

**Local Operator Surface**:
A same-machine browser web app that lets an operator speak to Oneesama, view
host visual context such as desktop/app preview and avatar, and inspect rich
debug state. It is the full operator-facing UI surface, not just a browser
client.
_Avoid_: legacy network client, operator client, debug-only page, control panel

**Single-Machine Operator Acceptance Lane**:
The primary acceptance path that validates Oneesama voice/control UX through the
Local Operator Surface on the same host Mac. It judges the human loop and
correlated evidence, not only whether a tool eventually completes.
_Avoid_: remote-device smoke, transport-only smoke, direct voice client

**Trusted Local Operator Mode**:
The V1 operating assumption that the Local Operator Surface is used by a trusted
operator on the same host machine. It keeps access-control hardening out of the
first acceptance path while still requiring an explicit local opt-in to open the
operator surface.
_Avoid_: production auth, public remote control

**Local Operator Reachability**:
The host-side evidence that tells an operator how the Local Operator Surface is
bound and opened, including loopback URL, bind mode, explicit opt-in state, and
reachability blockers. It proves the local surface can be reached from the host,
not that a separate device connected.
_Avoid_: remote peer proof, auth policy, network scan

**Host Visual Stream**:
The one-way set of visual sources sent from the host Mac into the Local Operator
Surface, such as desktop/app preview and avatar video. It does not include
streaming the operator computer's screen back to Oneesama, and it does not force
host-side final layout composition.
_Avoid_: second-device capture, bidirectional desktop share, host-baked layout

**Host Visual Publisher**:
The host-side browser page or process that captures a host desktop/app/avatar
source and publishes it as a one-way WebRTC video track to the Local Operator
Surface. It may use `getDisplayMedia` for real host capture or a diagnostic
canvas track for automated tests.
_Avoid_: operator capture, screenshot poller, bidirectional desktop control

**Operator Visual Composition**:
The Local Operator Surface's user-side composition of Host Visual Stream sources,
debug UI, and KWWK cursor/action overlays into a movable and resizable operator
layout. It produces a local Operator Composed Video Track from the browser canvas
for display and possible future export, while the host still publishes raw
source tracks.
_Avoid_: fixed host-side composite, single baked video layout

**Operator Composed Video Track**:
The local `MediaStreamTrack` generated by the Local Operator Surface from the
Operator Visual Composition canvas. It can be moved, resized, inspected, and
later published or recorded without asking the host Mac to rebuild its capture
layout. Layout changes are user-side composition edits over normalized source
rectangles; they must not require raw Host Visual Stream tracks to reconnect.
_Avoid_: host-baked track, screenshot composite, operator screen backflow

**Operator Voice Input**:
The operator's spoken input captured by the Local Operator Surface and delivered
to Oneesama for Conversation Engine turn formation. It is distinct from host-side
diagnostic recordings and transport-level audio traces.
_Avoid_: captions, browser track fallback, diagnostic recording as source of truth

**Always-On Operator Voice**:
The default Local Operator Surface voice mode where the microphone streams
Operator Voice Input continuously while the session is armed, and the
Conversation Engine owns speech detection, turn formation, and interruption.
_Avoid_: push-to-talk primary mode, record button, manual utterance capture

**Local Voice Activity Telemetry**:
Optional voice-activity evidence computed inside the Local Operator Surface for
operator feedback and diagnostics. It is not the source of truth for turn
formation when a Conversation Engine provides its own speech detection.
_Avoid_: local turn detection, required VAD gate

**Conversation Engine**:
The replaceable runtime component that turns voice/text input and context into
assistant output, tool calls, and interruption events. OpenAI Realtime is the V1
default implementation, not the product boundary.
_Avoid_: hardcoded Realtime sidecar, OpenAI-only runtime

**Conversation Engine Port**:
The provider-neutral boundary between Oneesama surfaces/tools and the active
Conversation Engine. It exposes canonical conversation events and tool calls
instead of provider-specific event shapes.
_Avoid_: raw provider events as product API, SDK history as shared contract

**Conversation Transport Selection**:
The startup decision that chooses the active Conversation Engine transport for
the Local Operator Surface. Explicit configuration wins; otherwise a configured
OpenAI API key selects OpenAI Realtime, while a missing key selects a clearly
marked diagnostic fallback.
_Avoid_: hidden mock default, provider lock-in, silent no-key downgrade

**Diagnostic Conversation Engine**:
A local replaceable Conversation Engine implementation used for tests and debug
runs. It accepts Local Operator Surface audio chunks and emits Canonical
Conversation Events without requiring a live realtime provider. It must be able
to emit the same canonical event vocabulary as live engines for harnesses and
failure injection, including engine errors.
_Avoid_: production model adapter, keyword fallback, deterministic product brain

**Canonical Conversation Event**:
A provider-neutral event emitted through the Conversation Engine Port to describe
speech, transcripts, assistant output, tool calls, interruptions, and engine
errors.
_Avoid_: provider raw event, SDK-specific callback

**Assistant Output State**:
The Local Operator Surface's rendered assistant response state derived from
Canonical Conversation Events, including visible text, local speaker playback,
audio queue, energy, and playback errors. It is what proves the operator can see
or hear the assistant, not merely that the engine emitted an event.
_Avoid_: raw response event, silent server-side completion, transcript-only proof

**Engine Control**:
A provider-neutral command sent from an operator surface to the active
Conversation Engine through the Conversation Engine Port, such as canceling the
current response, clearing audio buffers, resetting the session, or reconnecting.
Provider raw control events stay inside the active adapter.
_Avoid_: direct `response.cancel` UI API, provider-specific control surface

**Debug Panel**:
The high-information diagnostic area inside an operator-facing surface that
explains current audio, Conversation Engine, tool, KWWK, visual, and output
state plus the active blocker when something fails.
_Avoid_: HUD, raw logs, diagnostics JSON

**Primary Blocker Layer**:
The single operator-facing layer named by the Debug Panel for the latest bad
turn. It points to where attention should go first while the full Correlated
Turn Timeline keeps all candidate blockers available for drill-down.
_Avoid_: first error, raw exception, every blocker, hidden root cause

**Debug Report Artifact**:
A portable diagnostic snapshot produced from an operator-facing surface for
live debugging and acceptance review. It can be copied, downloaded, or marked
as interesting, and should preserve correlated state without requiring the
operator to inspect raw logs first.
_Avoid_: log dump, screenshot-only evidence, benchmark result

**Correlated Turn Timeline**:
A per-run diagnostic sequence that ties operator input, Conversation Engine
events, assistant output, tool routing, KWWK progress, verification, and
blockers into one readable chain. It exists to explain perceived responsiveness,
not to mirror every raw event.
_Avoid_: raw event list, provider trace, benchmark-only timing table

**KWWK Progress State**:
The operator-facing state of a host app-control job, including job id, target,
current phase, latest action, timings, cursor evidence, and blocker. It is the
live feedback contract for KWWK/CU, not the private planner trace.
_Avoid_: raw CU log, hidden tool result, final-only app mutation

**Tool Routing Evidence**:
The operator-visible proof that a Conversation Engine selected the expected
canonical tool, produced safe high-level arguments, and received function output
back through the Conversation Engine Port. It should make raw operation arrays
or coordinate leakage obvious.
_Avoid_: raw provider function-call event, hidden tool telemetry, final-only tool success

**Surface Adapter**:
A host-specific surface boundary that owns input/output policy and capabilities
for an environment such as local browser preview, embedded use, or the Local
Operator Surface.
_Avoid_: transport, client
