## Audit Strategy

Peng's explicit scope decision: oneesama replaces Cueboard's internal agent brain with an external Codex/Claude/Ollama runner invoked through `internal/agentrunner.Provider`. As a consequence, the entire Cueboard agent-framework — its core agent loop, framework bootstrap, environment hosts (local/sandbox VM/remote VM), OTLP telemetry, vmrpc bridge, websocket transport, backend LLM proxy, fly.io vault sidecar, Notion/Linear/Figma proxies, Google Calendar API client, and HTTP/file/api-proxy tools — is **product_excluded as a whole**.

This audit therefore:

1. Aggregates `core/`, `framework/`, `platform/`, `googlecalendar/`, and the credentialed parts of `integrations/` into **module-level rows** instead of enumerating every function (~2,300 functions across 169 files). Aggregate rows include a file count, function count, and the architectural reason.
2. Does per-function rows for the genuinely small or partially-ported modules: `app/`, `runtimepath/`, `configenv/`, `executil/`, `listenerset/`, and the Cueboard `cmd/` entrypoints (`slack-agentd`, `meetd`, `gcal-auth`). The remaining `cmd/` binaries (`agent-cli`, `test-vm`, `vmd`) are also product-excluded at module level.
3. Calls out the few non-credentialed `integrations/` and `transport/` helpers that have either a real oneesama analog or a worth-noting cueboard-only seam.

## High-Level Findings

- **P0 entrypoint architecture decision: cueboard ships separate binaries; oneesama ships one multiplexed binary.** Cueboard has `slack-agentd`, `meetd`, `agent-cli`, `gcal-auth`, `vmd`, `test-vm` as independent `cmd/...` mains. Oneesama collapses the two production paths into `cmd/oneesama` with subcommands `slack-agent` and `meeting-agent` dispatched through `httpserver.Serve(buildServer(cfg, logger))`. This is the right product decision — both Slack and meeting subagents now share config loading, slog setup, internalauth, healthz, CORS, request-log middleware, and graceful shutdown — but it means none of the cueboard per-binary `main.go` is verbatim_ported. The slack/meeting boot semantics are partial.

- **P0 secret/preflight surface is the cleanest port.** Cueboard's `scrubSlackAgentProcessSecrets()` is a verbatim port in `slackstartup.ScrubProcessSecrets()` with the same 11 env names in the same order (`SLACK_BOT_TOKEN`, `SLACK_APP_TOKEN`, `API_KEY`, `LINEAR_API_KEY`, `GOOGLE_*` 4, `FIGMA_API_KEY`, `NOTION_TOKEN`, `MEET_WEBHOOK_SECRET`). `probeSlackAgentBackendAuth` → `slackstartup.probeBackendAuth` is verbatim with identical fatal/non-fatal split on 401/403. `validateSlackAgentMeetdHealth` and `validateSlackAgentWebhookListen` are verbatim ports in `slackstartup.ValidateMeetdHealth` / `ValidateWebhookListen`. `validateSlackBashCommand` and the 7 `slackBashBlockRules` regexes are verbatim ported to `internal/slackagent/slack_safe_bash.go` (covered in task #165). This is the parity surface that is genuinely identical at the function level.

- **P0 environment-host / sandbox VM stack is dropped entirely.** Cueboard runs every agent action inside an `envhost.EnvironmentHost` — either an in-process local host, an Apple Virtualization VM sandbox (`envhost/sandbox` + `platform/vm` ~1,000+ funcs), or a remote VM driven through a vsock + websocket bridge (`envhost/remote` + `transport/ws`). All ~1,700 functions in `envhost/`, `transport/`, and `platform/vm` are product_excluded. Oneesama instead invokes an external command (`agentrunner.Provider`: codex, claude, ollama, command, dry-run) and returns the resulting transcript. This is intentional, but it means **every cueboard tool that depended on an envhost runtime bridge (`runtime_bridge_server.go`, `runtime_tool.go`, `runtime_http.go`, `runtime_config.go`, `file_stream.go`) has no functional equivalent at all** — neither in oneesama nor anywhere else in the AFK product. If a future product feature needs sandboxed code execution it is a green-field rebuild, not a port.

- **P1 config schema and YAML loader: cueboard's meetd merges YAML + env at the binary level; oneesama merges JSON + env at the library level.** `cmd/meetd/config.go:loadConfig()` is 200+ lines of explicit "env wins over YAML wins over default" merging across ~25 keys (`MEET_BOT_DISPLAY_NAME`, ASR provider/language/CLI, raw audio retention, caption language/DOM debug, audio backend, joiner xvfb, pulse sink/runtime, http addr, webhook URL/secret, digest URL/secret, watch interval). Oneesama replaces this with `pkg/config.Load()` reading a unified JSON config file (`SLACK_AGENT_CONFIG_FILE` / `ONEESAMA_CONFIG_FILE`) plus declarative `applyEnvOverrides(&cfg)` and `applyDerivedRuntimeDefaults(&cfg)`. The JSON shape uses `MeetingAgent`/`SlackAgent`/`Slack`/`AgentRunner`/`Meetd`/`OpenAI`/`Dialog`/`Logging`/`Paths`/`Persistence`. **The behavior is largely ported, but the file format changed and `yaml.KnownFields(true)` strictness is gone.** The cueboard `MEETD_CONFIG_FILE` (YAML) and `MEETD_SECRETS_FILE` (KEY=VALUE) split is replaced by a single JSON config + optional `*_SECRETS_FILE`. Operators with existing YAML configs need migration.

- **P1 `runtimepath.Layout` directory contract is gone.** Cueboard's `runtimepath/layout.go` (13 funcs, 72 lines) declared the `~/.bridge` filesystem layout: `sessions/`, `environment-store.json`, `envhost/`, `remote-host-store.json`, `workspace/`, `memory/`, `tmp/toolcall/`, `skills/`, `schedules/`, `agent_profiles/`. Oneesama has `pkg/config.Paths` for `WorkspaceDir`, `DataDir`, etc., but the structured "everything lives under one root and follows these subdir names" contract is absent. `sessions/`, `memory/`, `skills/`, `schedules/`, `agent_profiles/`, `envhost/`, `tmp/toolcall/` paths are all missing. This is consistent with the agent-framework being dropped (no sessions/skills/schedules in oneesama), but if oneesama ever reintroduces persistent session/skill metadata, the path contract should be rebuilt deliberately.

- **P2 small utilities: `listenerset.Set[T]` and `executil.ConfigureCommandCancellation` are missing without harm.** `listenerset.Set[T]` is a 6-method generic snapshot-iteration set; oneesama uses ad-hoc `map[K]struct{}` + `sync.RWMutex` in roughly four places (event listeners, scanner subscriptions, etc.) without consolidating into a generic. `executil.ConfigureCommandCancellation` is a single 50-line helper that puts a child process into its own pgroup, then sends `SIGTERM`/`SIGKILL` on context cancel. Oneesama's `agentrunner/process_unix.go` (29 lines) and `meetrunner/process_unix.go` re-implement this inline with their own `terminateCommand`. Both are intentional, not bugs.

## P0 Gaps

- ~~**`probeSlackAgentBackendAuth` is verbatim-ported into `slackstartup.probeBackendAuth` but `slackstartup.Validate` does not actually call it.**~~ **RESOLVED** (commit `12e09b2`): `Validate` now invokes `ValidateBackendAuth` which calls `probeBackendAuth(ctx, backendURL, apiKey)`. Fatal errors bubble up so bad BYOK keys fail startup fast.

- **`MEETD_CONFIG_FILE` YAML schema is replaced by JSON.** `cmd/meetd/config.go` reads a YAML file with `yaml.KnownFields(true)` strictness. Oneesama `pkg/config.Load` reads a JSON file (`SLACK_AGENT_CONFIG_FILE` / `ONEESAMA_CONFIG_FILE`) without unknown-field rejection. Existing meetd YAML configs need a migration story — there is no automatic conversion. **Open product decision.** Options: (a) keep the YAML reader on the meetd side until configs are migrated, (b) provide a `yaml → json` migration script, or (c) accept the breaking change as part of the rewrite.

## P1 Gaps

- **No `runtimepath.Layout` analog.** Cueboard's 72-line `Layout` type centralizes the `~/.bridge` directory tree (10 subdirs). Oneesama scatters paths across `pkg/config.Paths`, `pkg/config.Persistence`, and per-collection paths in the persistence provider. If oneesama ever reintroduces sessions/skills/schedules/agent_profiles, the path contract should be rebuilt as a single typed layout to keep ops mental model simple. **Open product decision** — no action needed until session/skill metadata returns.

- **`workspaceTemplateFS` (`go:embed`) is replaced by in-source string slice.** Cueboard's `workspace-template/` directory is checked-in markdown (`SOUL.md`, `AGENTS.md`, etc.) and copied at startup. Oneesama bakes the content into `DefaultWorkspaceTemplates` Go strings. This is easier to audit but harder to extend without recompiling. **Open product decision** — reintroduce only if operator customization matters.

- ~~**`executil.ConfigureCommandCancellation` is reinvented twice.**~~ **RESOLVED** (commit `75a3802`): new `internal/processutil` package exposes `PrepareGroup` + `KillGroup(label, cmd)` with unix / non-unix build-tag split. Both `agentrunner` and `meetrunner` now delegate. Behavior preserved; SIGTERM grace can be added later as a single-point change.

- **`listenerset.Set[T]` not consolidated.** Minor — about four places in oneesama use ad-hoc `map[K]struct{}+RWMutex` patterns where the cueboard generic would be cleaner. **Code-quality nit, not a behavior gap.**
